# PWA

TRINITY installs as a Progressive Web App: home-screen icon, standalone
window, offline shell, and — where the browser supports it — background sync.

## Manifest

Generated by `vite-plugin-pwa`. Key fields:

```json
{
  "name": "TRINITY",
  "short_name": "TRINITY",
  "display": "standalone",
  "background_color": "#0E1013",
  "theme_color": "#0E1013",
  "orientation": "portrait-primary"
}
```

Icons are the TRINITY mark at 192/512 px plus a maskable 512 px variant.

## Caching strategy

| Asset | Strategy |
|-------|----------|
| App shell (HTML/JS/CSS) | Precache, stale-while-revalidate |
| Fonts, icons | Cache-first, long TTL |
| API GET (read-only) | Network-first, short cache fallback |
| API mutations | Never cached; queued when offline |

The service worker is registered in production only; `devOptions.enabled`
is off so development is never served from a stale cache.

## Offline behaviour

Reads of *today's* dashboard fall back to the last cached payload and show a
subtle "last updated" timestamp — never a spinner forever, never a silent lie.
Write actions performed offline are queued and replayed on reconnect; the UI
marks them as pending rather than pretending they succeeded.

## Install prompt

The app never nags. A single, dismissible prompt appears after the user has
logged a second day of data, and stays dismissed once refused.

## Testing the PWA

```bash
cd frontend
npm run build && npm run preview

```
